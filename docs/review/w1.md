## First, a recap

Things said in lecture one that are not (yet) in the notes.

**Three more rat tricks** (beyond reuse-then-refactor and
keep-it-stochastic):

- **Active learning.** Do not learn from all the data. Build a
  tiny model, then use it to carefully select what to label
  next. That lets us ignore the uninformative, noisy, redundant
  data — in practice, most of the data. Active learners build
  competent models from a handful of labels (the ~50 from the
  maths) even across tens of thousands of variables. X values
  come free with every row; Y values cost a test drive.
- **Check the straw men.** Always baseline a sophisticated
  method against the dumbest possible one. Again and again the
  simple baseline is good enough, and the ceremony of the
  complex method was not worth it.
- **Exploit the repeated structure of SE data.** Software is
  written to be maintained by someone else, so it uses expected
  patterns — "natural" programs "are mostly simple and rather
  repetitive; thus they have usefully predictable statistical
  properties" ([the naturalness
  hypothesis](https://earlbarr.com/publications/naturalness_cacm.pdf)).
  That is why simple methods keep winning here.

**Two warnings:**

- **Bainbridge, Ironies of Automation (1983).** Automate the
  easy parts and humans keep the hard residue, plus a monitoring
  role they are cognitively bad at — about 30 minutes of useful
  attention. Watching a long Claude loop run is a Bainbridge
  situation.
- **Jevons paradox.** Cheaper coal burned more coal; the new
  expressway is the new traffic jam. Even if every bubble
  argument is wrong, cheap AI ends up scarce.

**Stochastic notes.** Random does not mean crazy: a random
variable comes from a known distribution with a mean and a
variance — structure you can exploit. Simulated annealing
escapes local maxima by sometimes accepting a worse solution.
PSO particles chase their own best find and the swarm's best
find — and since they never stop, the swarm re-converges when
the world changes.

**The sampling ladder.** Reward-free reinforcement learning (a
car that must satisfy laws not yet written): ~10^15 samples.
Know the goal (best-arm, the biased slot machine): ~10^4.
Accept near-enough (Cohen + Hamlet): ~50. Reuse someone else's
model and binary-chop: ~6.

**The tree demo.** `lua ezr-eg.lua --show`, on 398 cars:

<img src="../tree-demo.png" width=500>

Row one is the baseline: the mean of every column over all 398
rows. ▲ marks the best leaf, ▼ the worst. Reading down a
branch, constraints accumulate (each `|` is one more AND);
each split holds about half its parent's rows. On a 5,000-row
configuration problem with 17 choices, three variables
controlled everything — thirty years of software analytics
says that is the norm: a few variables matter, the rest can be
ignored.

## Answers

**I1.** experts are slow (hours for a handful); historical
labels unreliable (90% of "false positives" wrong); real
oracles ruinous (x264: 11 params, 1,000+ hours).
**I2.** `-` minimize goal, `+` maximize goal; neither = an
input (x) column.
**I3.** can't inspect it; changes without notice; confidently
wrong so every output needs a check; each generation costs
more (any one).

**M1.** `(1-p)^n`; at least one hit: `C = 1-(1-p)^n`.
**M2.** 0.35 = Cohen's negligible difference (in sd units);
6 = the ±3 sd width of a bell curve.
**M3.** ~50 (`log(0.05)/log(0.9417) = 49.8`).
**M4.** chopping a ranked list — halving, so `log2(50) ≈ 6`.
**M5.** one dimension, bell curve, independent draws; checked
by 100,000 runs over 127 MOOT tasks (flat at 95 above
budget≈50, check≈5).

**Q1.** 3 and 0.
**Q2.** the table; lists, dicts, objects.
**Q3.** "yes" — only `nil` and `false` are falsy in Lua;
Python's 0 is falsy.
**Q4.** `pairs` walks all keys in any order; `ipairs` walks
1..n and stops at the first `nil`.
**Q5.** a local, not an argument (reading-aid convention); a
third argument would silently land in `x`.
**Q6.** 100 — tables are references, not copies.
**Q7.** a global; typos silently create globals instead of
erroring.
**Q8.** `false`, then `2`.
**Q9.** same; the colon passes the receiver as a hidden first
argument (`i`).
**Q10.** `1 2 3`; a closure capturing `n`.
**Q11.** `"a"` — 0 is truthy in Lua (Python gives `"b"`); only
`nil` (besides `false`) is falsy.
**Q12.** `#u` is 2; only `pairs` visits `jump`; `pairs` order is
undefined, and this course grades ports by diff — output must be
identical on every run and runtime.
**Q13.** parentheses may be dropped when the single argument is
a string literal or a table constructor; a string literal needs
wrapping parens before you can call a method on it.
**Q14.** in its own upvalue `n`, created fresh by each
`counter()` call; nothing outside the closure holds a reference
to it.
**Q15.** `lo` gets the first return value, 1; the second (4) is
discarded. `print(minmax(3, 1, 4))` prints both: `1	4`.

**R1.** choosing the next thing to label; the uninformative,
noisy, redundant rest is ignored.
**R2.** X cheap (visible on every row), Y dear (each label
costs a test drive / a build / an expert's hour).
**R3.** the dumbest possible baseline; that the simple thing is
often good enough and the complex method's ceremony was not
worth it.
**R4.** the naturalness hypothesis: code is written to be
maintained, so it is repetitive, so it is statistically
predictable.
**R5.** reuse: skill i+1 mostly rewires machinery built for
skills 1..i; only the first skill pays for the shared data
structures.
**R6.** ChatGPT mode = S;N;S (symbols in, net thinks, symbols
out). Any other row + example, e.g. N[S]: an LLM calls a SAT
solver mid-answer; N;S: the net proposes, a model checker
verifies.
**R7.** the cheap symbolic optimizer (EZR) ran first; its best
results became the seed prompt for the LLM.
**R8.** neural to specify (dialog turns your words into a
spec); symbolic to execute (fast, cheap, inspectable code under
the hood).
**R9.** the hard residue plus a monitoring role; ~30 minutes;
because you are a human monitoring an automated process you no
longer practice.
**R10.** cheaper means used more, which means congested and
expensive again; so even good cheap AI ends up scarce.
**R11.** "How will you find senior programmers in ten years if
you are not hiring and training junior ones?"

**M6.** reward-free RL (~10^15) > best-arm (~10^4) >
near-enough (~50) > binary chop (~6). Collapses: knowing the
goal; accepting near-enough (Cohen's 6% + Hamlet); borrowing a
model that ranks pairs (log2).
**M7.** with some probability it accepts a worse solution, so
it can climb out of holes.
**M8.** its own best-so-far and the swarm's global best (plus
noise); the particles never stop, so when the world changes the
swarm re-converges — free maintenance.
**M9.** a known distribution, with a mean and a variance.

**T1.** the baseline: the mean of every column over all rows.
**T2.** the best (▲) and worst (▼) leaves, by distance to
heaven.
**T3.** constraints, ANDed one per level; each split keeps
about half its parent's rows.
**T4.** in any business problem a few variables matter and the
rest can be ignored.
**T5.** uppercase = numeric column; lowercase = symbolic;
trailing `X` = ignore the column; `?` = missing value.

**S1.** so random runs can be replayed exactly — for debugging,
and for grading by diff.
**S2.** the same stream of numbers; because grading is diff:
same seed must mean the SAME 20 numbers across Lua and Python.
**S3.** imported (sit quietly, only define things) vs run as
the driver (do something). Python: `if __name__ == "__main__"`.
Here: the `go(eg)` guard, which checks the file is `arg[0]`.
**S4.** the `--seed=42` flag updates `the.seed`; `random.seed(the.seed)`
resets the stream; the name `rand` is looked up as `test_rand`
and called.

**Q16.** the last element; Lua indexes from 1, so `#t` is the
last position.
**Q17.** the loop calls its iterator function each pass and
stops when it returns `nil`.
**Q18.** operator overloading — the metamethod for `-`; Python
calls it a dunder (`__sub__`).
**Q19.** lua5.4 prints `3.0` where LuaJIT prints `3`, so raw
floats break byte-identical diffs; round/format first.

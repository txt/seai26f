# w3: lecture notes + exam questions

## What the Aug 31 lecture added, beyond gloss1 and gloss2

Reconstructed from the transcript. The lecture walked
[gloss2](https://txt.github.io/seai26f/gloss2.html) (closures,
iterators, metatables, metamethods, the little verbs, the pool
algebra, metric laws, property-based testing); these notes keep
only what the spoken version added on top.

**N1. The Aha heuristic, named.** "Unknowns assume the worst"
is not folklore — it comes from David Aha's instance-based
learning work (Aha, Kibler & Albert 1991). When ignorance is
total, assume maximum distance: two "?" cells are distance 1;
a missing number is pushed to whichever end is further from the
known one. Now cited in the gloss1 distx entry.

**N2. x cheap, y expensive.** The x columns are cheap
observables; the y columns are verdicts. A used car's color,
cylinders and weight are free at a glance; its honest
miles-per-gallon needs a long test drive. Which degree you
enrolled in is an x, known today; whether it was the right
degree is a y that may take decades to label. We are rich in x,
poor in y — the economics behind every active-learning week to
come. Now in the gloss1 disty entry.

**N3. Welford generalizes.** The mean is the first moment, sd
comes from the second, skew from the third — and Welford-style
incremental update extends to all of them. Because summaries
add AND subtract in O(1), one pass can score every cut of a
sorted column, and active learners that update incrementally
can run orders faster than ones that rebuild.

**N4. Why noir collapses to two scales.** The interval/ratio
distinction rests on a fixed zero point — but under incremental
learning the observed zero can shift or vanish, so this code
never trusts it. Everything numeric is a float; symbols get
counted; nothing else.

**N5. show's recursion bomb.** show prints nested tables by
calling itself on every value. Give it a structure whose child
points back at its parent and it recurses forever. The fix, if
you ever need it: carry a depth counter, stop at 100.

**N6. DSU arithmetic.** A comparator sort computes the key
inside every comparison: about 2n·log n key calls. Decorate
first and it is n calls plus a plain sort. So keysort pays off
exactly when the key is expensive (disty!) and is pointless
when the key is cheap. Python's sorted(key=) does the same
decoration internally.

**N7. The file-handle confession.** Opening a file is a
system call — expensive, so csv does it once, outside the
returned closure. And the Python port should really say
`with open(file) as f:` — a context manager frees the handle
even when the loop crashes.

**N8. Caching the centroid.** A table caches its column-middles
(`i.mid`) and invalidates the cache (`i.mid = nil`) whenever a
row is added or removed: memoization, plus the discipline of
knowing exactly which writes stale your cache.

**N9. Polymorphism yes, inheritance no.** This code sends the
same message (mid, div, dist...) to different receivers and
lets the metatable dispatch — but it never builds inheritance
hierarchies. One layer of dispatch is explainable; deep
hierarchies are where behavior goes to hide.

**N10. Aggregation vs Pareto, the confession.** The standard
objection to an aggregation function like disty: it silently
assumes all goals weigh the same, and Pareto methods were
invented to avoid exactly that. The lecturer avoided
aggregation for 20 years for that reason — then experiments on
127 SE optimization problems showed the aggregate-and-zoom
approach winning. Know the objection AND the evidence.

# Nine exam-style questions

Each: (a) recall, then (b) a bug hunt in code. The bugs are
small; the issues they reflect are not. Answers at the bottom
(practice bank — do not reuse verbatim on real exams).

**Q1 — the closure that forgot**

a) What two things make up a closure?

b) A student "tidies" csv by moving the open inside. What does
`for row in csv(f)` now print, and when does it stop?

```lua
function csv(file)
  return function(    t,l,f)
    f = io.lines(pathname(file))
    for line in f do
      l = line:gsub("%%.*",""):match"^%s*(.-)%s*$"
      if l ~= "" then
        t={}
        for s in (l..","):gmatch"(.-)," do t[#t+1]=thing(s) end
        return t end end end end
```

**Q2 — the iterator that quit early**

a) What makes Lua's generic `for` loop stop?

b) This reader crashes on no line but "works" on the demo file.
Feed it a csv with one comment line in the middle. How many rows
come back, and why is the failure silent?

```lua
function csv(file,    f)
  f = io.lines(pathname(file))
  return function(    t,l)
    l = f()
    if l then
      l = l:gsub("%%.*",""):match"^%s*(.-)%s*$"
      if l ~= "" then
        t={}
        for s in (l..","):gmatch"(.-)," do t[#t+1]=thing(s) end
        return t end end end end
```

**Q3 — the missing redirect**

a) When `n:mid()` finds no `mid` inside `n`, where does Lua look
next?

b) One assignment is gone. What exactly happens on the first
`n:mid()`, and why does `print(n)` still work?

```lua
function new(kl,t)
  kl.__tostring = show
  return setmetatable(t,kl) end
```

**Q4 — subtraction, minus the gap**

a) In the pooled-variance formula, what does the
`d*d*i.n*j.n/n` term measure?

b) An LLM "simplifies" NUM.__sub as below. For which pairs of
summaries does `--without` still pass, and what happens to the
reported sd everywhere else?

```lua
function NUM.__sub(i,j,    n)
  n = i.n - j.n
  if n < 1 then return Num(i.name, i.at) end
  return new(NUM, {name=i.name, at=i.at, heaven=i.heaven,
                   n=n, mu=(i.n*i.mu - j.n*j.mu) / n,
                   m2=max(0, i.m2 - j.m2)}) end
```

**Q5 — the tie that moved**

a) Roughly how many key-function calls does a comparator sort of
n rows make, versus keysort's decorate-first approach?

b) The `ix` bookkeeping got dropped. The sort is still
"correct" — so what rots, and who notices first?

```lua
function keysort(t,f,    px)
  px = {}
  for _, v in ipairs(t) do px[v] = f(v) end
  return sorted(t, function(u,v) return px[u] < px[v] end) end
```

**Q6 — the printer that never returns**

b) Run the three lines below. What happens, and what one-line

**Q7 — the optimistic unknown**

a) State the Aha heuristic for missing values.

b) An LLM flips one return value, arguing "two unknowns are
probably the same". Which rows now cluster together, and why is
every structure built on those clusters fantasy?

```lua
function SYM.dist(i,a,b)
  if a == "?" and b == "?" then return 0 end
  return a ~= b and 1 or 0 end
```

**Q8 — the free labels**

**Q9 — one number to rule them all**

a) What does an aggregation function do with N goals, and which
function is this course's aggregation function?

b) State the standard Pareto-community objection to the line
below — and the empirical rebuttal from the lecture.

```lua
return minkowski(i.cols.y, function(y)
         return abs(y:norm(row[y.at]) - y.heaven) end)
```

## Answers

**A1.** A closure is code plus the variables captured where it
was born. Moved inside, `io.lines` re-opens the file on EVERY
call, so the reader returns the first line (the header) forever:
`for row in csv(f)` prints the header row in an infinite loop
and never stops — nil never arrives. Setup belongs outside the
returned function; that is the whole point of the closure.

**A2.** The loop stops when the iterator returns nil. Without
the inner `for line in f do` retry-loop, a comment line
scrubs to "" and the function falls through — returning nil
mid-file. The for-loop takes that as end-of-stream: every row
after the comment is silently dropped. Nothing crashes; row
counts are just quietly wrong (the demo's assert on 399 rows
is what would catch it).

**A3.** The metatable's `__index`. With `kl.__index = kl` gone,
a miss on `n` falls through to nothing: `n:mid()` raises
"attempt to call a nil value (method 'mid')" — every demo dies
at its first method call. `print(n)` still works because
`__tostring` is its own metamethod, set independently on the
metatable.

**A4.** It measures the spread contributed by the gap between
the two group means — much of a combined curve's width IS the
distance between its humps. Dropping it: `--without` still
passes whenever the two summaries share a mean (d = 0), so
symmetric tests stay green; everywhere else m2 is too big and
the reported sd inflates. Deep lesson: variance does not
decompose without the between-groups term.

**A5.** Comparator: the key runs inside each of ~n·log n
comparisons, twice — about 2n·log n calls. keysort: n calls.
Dropping `ix`: `table.sort` is unstable, so tied rows land in
different orders on different Lua versions (and across runs of
LuaJIT vs 5.4). Output is still "sorted" — but frozen
transcripts stop diffing clean, and the person who notices
first is whoever grades your port by diff.

**A6.** Tables nest, so the printer must recurse. `node.parent
= node` is a cycle: show calls show calls show until the stack
explodes ("stack overflow"). Defense: thread a depth argument —
`function show(t, d)` — and return "..." once d passes some
limit, recursing with d+1.

**A7.** When ignorance is total, assume maximum distance
(Aha, Kibler & Albert 1991). Flipped to 0, any two rows with
"?" in the same column now look identical there — rows FULL of
missing values cluster tightly together, poles get chosen from
them, and halves split on shared ignorance rather than shared
structure. Optimism about unknowns manufactures similarity that
is not in the data.

**A8.** x columns (cheap observables: color, cylinders, weight
— free at a glance) versus y columns (verdicts: honest mpg
needs a long test drive). The warm-up calls disty on every row;
disty reads the goal columns, and goals are labels. On a live
model that is the entire labelling budget — spent before the
learner starts. The learner then "finds" good rows using
answers it already paid to see: label leakage, results fiction.

**A9.** Collapse N goals to one number — here disty, the
Minkowski gap from a row's goals to heaven. Objection:
aggregation silently assumes all goals weigh the same, which is
exactly what Pareto methods exist to avoid. Rebuttal: across
127 SE optimization problems, aggregate-and-zoom won or tied
against frontier-chasing rivals while running orders faster —
know both the objection and the evidence.

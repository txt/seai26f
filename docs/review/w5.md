# w5: lecture notes + exam questions

## What the Sep 21 lecture added, beyond gloss3 and gloss4

Reconstructed from the transcript. The lecture re-ran fastmap
live (with students as rows), then spent most of the night on
one claim: the cluster tree you already own is nine tools
wearing one coat. New glossary entries from this night:
[synonyms](../lect/glossary.md#synonyms),
[cluster naming](../lect/glossary.md#clusternaming),
[weak indicators](../lect/glossary.md#weakindicators),
[data collapse](../lect/glossary.md#data-collapse),
[certification envelope](../lect/glossary.md#certification-envelope),
[knee](../lect/glossary.md#knee).

**N1. Supervised halving costs two labels a level.** Unsupervised
fastmap needs no y at all. Label just the two poles, keep the
half beside the better pole, recurse — and a good leaf arrives
after about 2·log2(n) labels. That is the whole of sway1, and
the reason a course about optimization spends five weeks on
distance.

**N2. Poles come from a sample, on purpose.** `the.few=128`: the
poles are hunted inside 128 randomly drawn rows, not all
100,000. Two far-apart rows out of 128 are already near the
diameter of the cloud, and the split only needs poles that are
far and roughly opposed, not optimal.

**N3. Weak indicators, and how to hedge them.** Fastmap is a
guess, so do not bet the farm on one reading of it. sway3 keeps
α=0.66 of the pool instead of half (`keepf`) and labels β=4 rows
per level instead of 2 (`more`) — a gentler cull, steadied by
more evidence. A large Monte Carlo study picked those numbers.
There was a sway2; it was a bad idea and nothing descends from it.

**N4. Restart when the budget outlives the pool.** A log-n chop
hits a tiny leaf long before 50 labels are spent. So `acquirer`
reshuffles and descends again — anchored at the best and worst
rows labelled SO FAR, so every restart inherits everything paid
for to date.

**N5. Support, not just purity.** A split that isolates one
outlier can look perfect. The weighted score (`val`) charges a
cut for the SIZE of each side, and `big` refuses any cut leaving
fewer than `the.leaf` rows on a side. Purity without support is
noise wearing a suit.

**N6. Anomaly detection = a distance, not a new algorithm.** Each
leaf knows how spread out its own rows are. A new row that
reaches a leaf but sits far outside that spread is an anomaly.
Wrap that check around any learner and you get a certification
envelope: an answer, plus a red light saying do not trust this
answer. NASA's Crater model, asked about debris 400 times bigger
than anything it was calibrated on, had no such light; Columbia
and seven astronauts were lost in 2003.

**N7. Benchmarking is anomaly detection with a different name.**
Cluster the reference population (60 car yards, say) and ask
where this one lands: near the good cluster, or far from every
cluster? Same code, different sentence. This is the first
example of the night's big claim.

**N8. Nine boxes, one machine.** Buse & Zimmermann's analytics
grid (trends, alerts, forecasting; summarization, overlays,
goals; modeling, benchmarking, simulation) maps onto the cluster
tree: leaf mean = regression, leaf mode = classification, prune
the worse half = optimization, far-from-leaf = alerts, read the
tree = summarization, mutate-then-re-drop = forecasting and
simulation. The prediction that makes it science: each new skill
needs less new code than the last. That is the ugrad project, and
an LLM asked each skill cold is the rival.

**N9. Collapse the rows, then collapse the columns.** Evidence,
not rows, builds a model, so rows collapse to prototypes (a
tenth, a hundredth). For any one target only about √n of n
columns matter. What is left is a small corner — which is what
Peters' LACE shares instead of the data, and which is why
"always get more data" is advice for dialog and translation, not
for tables.

**N10. Reading a literature is the same trick.** In a field of N
researchers, about √N write what half the field uses. Sort a
search by citations, draw the chord from first to last point,
and read above the knee (20–30 papers). Then snowball backward
(the classic everyone cites) and forward (who cites the classic
now), tag each paper with three or four features, draw the Venn
diagram, and aim at the empty cell. A warning for the grad
project: reproduction packages are standard now, but only 20–40%
of them will actually run and reproduce on your machine — so do
not meet them for the first time the night before a deadline.

## Exam questions

**Q1. The budget that overspends**

a) In one `acquire` sweep, how many rows get labelled per round,
and what stops the sweep?

b) What does the change below do to a run with `budget=50`, and
why does the sweep's accuracy story become unreportable?

```lua
more, new = the.more, {}
```

**Q2. The restart that forgets**

a) Why does `acquirer` run more than one descent?

b) The last line picks the anchors for the next descent. What is
wrong with this version, and what does the next descent then do
with its labels?

```lua
t = keysort(lab, i:Y())
lo, hi = t[1], t[2]
```

**Q3. The pure little split**

a) Define support for a cut, and say why `val` weights each
side's diversity by that side's row count.

b) The guard below is `big` with the lower test deleted. Which
cuts now win, and why does the tree get worse while its training
score gets better?

```lua
function big(lo,n)
  return lo <= n - the.leaf end
```

**Q4. One machine, two jobs**

a) `TREE.leaf` walks a row down and returns `t.mu`. Why is that
a regression?

b) The same dozen lines must classify instead. Which ONE thing
changes, and what does `mu` become?

```lua
function TREE.leaf(t,tbl,row,    c)
  while t.at do
    c = tbl.cols.all[t.at]
    t = c:holds(row[t.at], t.v) and t.yes or t.no end
  return t.mu end
```

**Q5. The confident stranger**

a) Define a certification envelope.

b) Feed the code above a row utterly unlike anything in the
training data. What does it return, what does it NOT return, and
what single extra measurement — using only machinery from weeks
2 and 3 — fixes that?

**Q6. Benchmarking, renamed**

a) State what an anomaly is, in terms of a leaf and a distance.

b) You benchmark 60 car yards and are asked "is yard 31 doing
well?". Explain why this is the same computation as Q6(a), and
name the one thing you must change.

**Q7. Forecasting with the world's smallest mutator**

a) What is a what-if query?

b) You believe cars will lose a wheel this decade. You copy real
rows, set wheels from 4 to 3, and drop the copies back down the
tree. Suppose every copy lands in its original leaf. Give the two
different readings of that result, and say what you would measure
to tell them apart.

**Q8. Where to stop reading**

a) Define the knee of a sorted curve.

b) A citation-sorted search returns these counts. Say roughly
where the knee falls, and state what it would mean for your
reading list if the curve were instead flat (200, 190, 185,
180...).

```
210, 180, 96, 61, 55, 31, 30, 12, 9, 7, 6, 5, 4, 4, 3, 2, 2
```

**Q9. Important, or actionable?**

a) What does a tree branch say that a feature-importance ranking
does not?

b) A safety report says "tires are important" and your tree says
"tread depth <= 2mm". Only one of these can be argued with by a
fleet manager. Say which, and why the other one cannot be acted
on.

**Q10. Why the corner is enough**

a) State the two collapses: rows to what, and columns to how
many?

b) Your friend says "any data you delete loses accuracy". Give
the case where they are right and the case where they are wrong,
and say what LACE publishes instead of the data.

## Answers

*A practice bank. These are not the exam.*

**A1.** Up to `the.more` (4) labels per round, and the sweep
stops when the pool falls below `2*the.leaf` rows or when
`#lab >= cap`. With the change, `more` no longer shrinks as the
budget runs out, so a sweep can spend past `cap` — the run then
reports a score for "50 labels" that was bought with more than
50. The whole point of active learning is the price tag, so a
result whose price is unknown says nothing.

**A2.** Because the pool dries out long before the budget does:
each descent is a log-n chop, so it reaches a tiny leaf with
labels still in hand. Restarting reuses everything labelled so
far. With `t[1], t[2]` the two anchors are the best and the
SECOND-best row — two nearby points, not opposed ones. The
projection then divides by a near-zero `c` and rank order becomes
noise, so the next descent spends real labels on a random cull.
It must be `t[1], t[#t]`: best and worst.

**A3.** Support is how many rows a cut leaves on each side. A
side holding one row has diversity 0 for free — it cannot
disagree with itself — so unweighted scores reward peeling off
single outliers. Weighting by `n` asks instead for the expected
diversity a random row lives with after the cut. With the lower
test gone, `big` no longer refuses tiny left sides, so cuts that
isolate one or two rows win. Training loss drops (each little
leaf is perfectly pure) while the tree learns the noise: it is
memorizing rows instead of summarizing groups.

**A4.** It is a regression because `mu` is the mean of the y
values of the rows in that leaf: similar rows, so their average
is a first-pass prediction for a new arrival. To classify,
change the accumulator: build each node's y summary with `Sym`
rather than `Num`, and `mid` (hence `mu`) returns the mode, the
most common class. Same walk, same tree code — the column
protocol absorbs the difference.

**A5.** A certification envelope is a check around a model that
reports when the question falls outside the data the model was
built from, so the answer arrives with a warning rather than
alone. The code returns a confident number; it does not return
any statement about whether the row was like anything it has
seen. The fix: at the leaf, compare `distx` from the new row to
the leaf's rows against the typical distance among those rows
(or to the leaf's own poles). Far outside means answer plus red
light. Crater answered about 1,200 cubic inches having been
fitted on 3 — with the envelope, that reads "do not use this
number".

**A6.** An anomaly is a row that reaches its nearest leaf but
sits far outside the distances normally seen inside that leaf.
For the car yards: cluster the 60 yards, drop yard 31 in, and
ask the same question — near the good-end leaf, near a mid leaf,
or far from every leaf? The only thing that changes is the
reference population you clustered (the other yards, rather than
past examples of your own). Benchmarking is anomaly detection
with a different word attached.

**A7.** A what-if query changes some x values of real rows and
asks what the model now predicts. If every mutated copy lands in
its original leaf, either (i) the tree never cut on wheels, so
the mutation is invisible to this model, or (ii) the tree did cut
on wheels but 4→3 does not cross the threshold. Check which by
looking at the tree: does `wheels` appear in any branch, and if
so, at what value? Reading (i) is itself a finding — under these
goals, that column does not matter.

**A8.** The knee is the point furthest from the chord drawn from
the first point of the sorted curve to the last. Here the curve
falls off a cliff after the low-30s, so the knee is about the
first six or seven papers (the 31+ group) — that is the reading
set. A flat curve (200, 190, 185, ...) has no knee worth the
name: no small set dominates, which means either the query is
too broad, or you are looking at a field with no core, and you
should fix the query before reading anything.

**A9.** A branch is a test — a column AND a value — so it names
a state of the world you can change: bald tires, tread under
2mm, the cap turned through 180 degrees. An importance ranking
names only the column, so it tells you where to look and never
what to do. The fleet manager can argue with "tread depth <=
2mm" (measure it, dispute the threshold, act on it) but cannot
argue with "tires are important".

**A10.** Rows collapse to prototypes — a few dozen exemplars,
often a tenth or a hundredth of the data — and for any one
target only about √n of n columns carry signal. Your friend is
right for tasks that need coverage of endless special cases
(dialog, translation, "how do I port this idiom to Rust"), where
every rare example earns its keep. They are wrong for
tables — classification, regression, optimization — where a
model is built from repeated evidence and repetition compresses.
LACE publishes the corner: prototypes of the important columns,
mutated within the structure that holds there. Everything not
published is private by construction.
